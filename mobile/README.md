# OnClock Mobile (iOS)

Native iOS shell around the existing Next.js employee portal at `/portal/*`.
Built with **Capacitor** — the WebView loads the live portal, native plugins
provide geolocation, camera, push, and persistent session.

## Project layout

```
mobile/
├── capacitor.config.ts      ← server URL, plugin config
├── www/                     ← fallback shell shown briefly at launch
├── ios/                     ← native Xcode project (generated by `cap add ios`)
│   └── App/
│       ├── App.xcodeproj/
│       └── App/Info.plist   ← permission usage strings
└── package.json
```

## Development workflow

### Prereqs (one-time)

- Xcode (latest from App Store)
- Xcode Command Line Tools: `xcode-select --install`
- CocoaPods: `sudo gem install cocoapods`
- Apple Developer account signed in via Xcode → Settings → Accounts

### Daily flow

```bash
cd mobile

# After changing capacitor.config.ts or installing plugins:
npm run ios:sync

# Open Xcode and run on simulator / device:
npm run ios:open
# (or: npm run ios:run)
```

In Xcode:
1. Select a Simulator (or your iPhone connected via cable)
2. Cmd-R to build & run

### Pointing at local dev

Edit `capacitor.config.ts`:
```ts
server: {
  url: 'http://192.168.1.x:3000/portal',  // your Mac LAN IP
  cleartext: true,                         // for http:// during dev only
  allowNavigation: ['192.168.1.x', 'onclock.ph'],
}
```
Then `npm run ios:sync`.

### Pointing at production
Leave `capacitor.config.ts` set to `https://onclock.ph/portal` (or whichever
real subdomain you use).

## Permission strings (already set in Info.plist)

- `NSLocationWhenInUseUsageDescription` — for clock-in geofence
- `NSCameraUsageDescription` — for clock-in selfie
- `NSPhotoLibraryUsageDescription`, `NSPhotoLibraryAddUsageDescription` — saving payslips
- `NSFaceIDUsageDescription` — biometric unlock (future)

## Plugins included

| Plugin | Use case |
|---|---|
| `@capacitor/geolocation` | Clock-in geofence |
| `@capacitor/camera` | Clock-in selfie |
| `@capacitor/push-notifications` | Approval / reminder alerts |
| `@capacitor/preferences` | Persistent session (replaces localStorage in mobile context) |
| `@capacitor/app` | Back-button / deep-link handling |
| `@capacitor/browser` | Open external links (forgot-password etc.) in Safari |
| `@capacitor/splash-screen` | Loading state while WebView boots |

## Bridging the portal to native APIs

The portal already calls `navigator.geolocation` and `navigator.mediaDevices.getUserMedia`,
which Capacitor proxies to native APIs automatically — no portal code change needed
for basic clock-in.

For push notifications and biometric unlock, the portal needs to detect
"is this running inside the native app" and call Capacitor APIs:

```ts
import { Capacitor } from '@capacitor/core'
if (Capacitor.isNativePlatform()) {
  const { PushNotifications } = await import('@capacitor/push-notifications')
  await PushNotifications.requestPermissions()
  await PushNotifications.register()
}
```

That bridging can come later — v1 just wraps the portal as-is.
